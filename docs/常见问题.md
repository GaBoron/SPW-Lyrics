# 常见问题

正常操作见[使用说明](使用说明.md)，安装和兼容要求见 [README](../README.md)。本页按症状排查。

## 安装、更新与入口

### 安装后看不到插件

确认使用与 SPW 匹配的完整安装包，在「设置 → 创意工坊」中导入并启用。当前包为 `.spmod`，不要提前解压或重新打包。SPW 更新后仍无法加载时，完全退出后重启；需要旧宿主版本时，按 [README](../README.md) 选择对应版本。

### 更新时无法移动旧插件目录

1. 停用 SPW Lyrics。
2. 完全退出 SPW，包括托盘和创意工坊发布器。
3. 重新启动，保持插件停用，导入完整安装包后再启用。

旧包中的 JNA 等文件可能仍被进程占用，重启用于释放文件锁。不要在 SPW 运行时手动处理插件目录；仍失败时请保留完整报错。

### 管理页崩溃，或提示原生渲染错误

`UnsatisfiedLinkError`、`RenderNodeContext_nMake` 通常与渲染库不匹配有关。完全退出 SPW，安装匹配的完整插件包，再重启；不要自行替换宿主 DLL / `.so`。仍崩溃时暂时停用插件，并反馈系统、SPW / 插件版本及异常。

### 顶部没有歌词管理，或播放器菜单缺少入口

授予「类变换」权限后重新启用，等待后台接入完成。播放器菜单单独失败时，可先使用顶部入口。

成功接入后会缓存目标，缓存失效时自动重新定位。需要强制重新定位时，关闭 SPW，将 `cache/宿主Hook.properties` 移入回收站，再启动。仍失败时请反馈版本和完整异常；宿主结构变化可能需要插件适配。

## 搜索与匹配

### 自动搜索失败或没有候选

打开手动搜索，缩短关键词、指定单个来源，并悬停查看词源状态：

| 状态 | 处理方式 |
| --- | --- |
| 未配置 | LrcShare 需先填写自己的 API Key |
| 可用但无候选 | 调整关键词，不代表网络失败 |
| 失败 / 超时 | 检查相应服务的网络、代理，稍后重试或换来源 |
| AMLL 索引下载 / 更新失败 | 有旧索引时仍可搜索；首次下载在后台进行，检查网络后重试 |

失败结果不会缓存，不需要为此反复重装。若能找到候选但自动未采用，先预览并核对录音版本，再决定是否手动应用。

### 一直显示本地歌词

检查[自动替换策略](使用说明.md#自动替换策略)、单曲是否选择过「切回本地歌词」，以及是否读到了优先转换的本地 TTML。也可能是在线来源尚无可靠结果。

「恢复自动匹配」清除单曲选择并重试；要覆盖本地 TTML，可直接手动应用在线候选。使用 AMLL into SPW 时，还需检查它的[本地 TTML 优先级](使用说明.md#与-amll-into-spw-一起使用)。

### 歌词是另一首歌，或录音版本不对

在手动搜索中核对歌手、专辑、时长及 Live、Remix、伴奏、翻唱等版本，预览正确后再应用；不合适时可「切回本地歌词」。匹配分仅供排序，不能替代预览。

切歌后仍显示旧歌词时，先切到其他歌曲再切回，并刷新搜索页的当前歌曲。可通过「恢复自动匹配」重取；仍异常时按[缓存说明](使用说明.md#本地缓存)重建该曲缓存，记录前后两首歌与操作顺序反馈。

### 某个来源有歌词，却选了其他来源

默认类型优先：例如 AMLL 只有逐行、QQ 有逐字时会选择 QQ。需要固定来源顺序时，改为「歌词来源优先」并调整列表；填写错误可「重置歌词排序」。两种模式都会检查录音版本，详见[选择设置](使用说明.md#自动替换策略)。

## 显示与同步

### 文字正确，但时间不准

先核对录音版本和时长，尝试其他候选。整首固定偏差可用[单曲延迟](使用说明.md#调整歌词延迟)：正数延后，负数提前；逐渐增大的偏差需要换歌词或重做时间轴。

找到或保存歌词后没有刷新时，切到另一首歌再切回。SPW 更新后持续无法自动刷新，请反馈宿主版本和异常。

### 缺少翻译、音译或逐字效果

这些内容取决于所选来源。先在预览中确认，再换候选；原生 TTML 和普通 SPW 歌词的呈现也可能不同。

### AMLL into SPW 没有显示所选 TTML

确认两个插件已启用，AMLL into SPW 支持 TTML 互通并获得所需权限；可切歌触发重新提供。它自行读取的本地 TTML 优先于外部选择，按[互通说明](使用说明.md#与-amll-into-spw-一起使用)检查。

「切回本地歌词」会撤回外部结果，但不会隐藏本地 TTML。接收器不可用时仍提供普通 SPW 歌词；仅某份 TTML 异常时，换候选比较，并反馈两个插件版本与歌曲信息。

## 编辑与打轴

### 歌曲文件写入失败

核对顶部目标路径、[支持的文件与格式](使用说明.md#编辑歌曲元数据和内嵌歌词)，再按提示处理：

- 文件被播放器或同步程序占用：切换到其他歌曲或等待同步完成后重试，草稿会保留。
- 文件已被其他程序修改：先复制需要保留的草稿，再重新读取文件。
- 提示已回退原文件：排除占用或格式问题后重试。
- 提示回退失败并给出恢复文件路径：停止播放，保留该恢复文件，按提示恢复原歌曲。

保存后歌名、封面仍旧时，重新扫描 SPW 曲库再切歌。歌词仍旧时，选择「切回本地歌词」并检查同名歌词文件。成功写入有损格式后，恢复丢失信息需重新导入原始歌词。

### 频谱不可用或分析超时

启用 [SPW Media Runtime](使用说明.md#频谱与波形辅助) 后点击「重新分析」。仍失败时确认音频可读，尝试缩小时间窗；Runtime 重启或更新后重新分析即可。键盘打轴本身使用 SPW 播放，不要求频谱依赖。

### 打轴快捷键不生效

先让 SPW 播放正在编辑的文件，再点一个词或「启用键盘」。焦点在输入框时字母键用于输入；切歌或跳转会取消正在按下的录入。操作与判定方式见[逐字打轴](使用说明.md#跟随宿主播放打轴)。

## 缓存与问题反馈

清理前关闭 SPW，仅将需要重建的对应文件移入回收站；不同文件的作用见[本地缓存](使用说明.md#本地缓存)。清空整个 `cache` 会丢失单曲手动选择，缓存目录外的延迟和校准仍保留。

仍有问题可提交 [Issue](https://github.com/GaBoron/SPW-Lyrics/issues)，附系统、SPW / 插件版本、复现步骤和相关异常。匹配问题再附歌名、歌手、专辑、时长、来源及截图；无需整首歌词或音频，勿公开 API Key。
