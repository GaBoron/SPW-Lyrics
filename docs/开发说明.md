# 开发与构建

面向构建、排错和扩展插件的开发者。安装与兼容要求见 [README](../README.md)，功能操作见[使用说明](使用说明.md)。

## 构建与依赖

需要 **JDK 25**，依赖和插件版本以 [build.gradle.kts](../build.gradle.kts) 为准。当前编译接口为 Workshop API `0.1.0-dev23`，不兼容旧 API。

Windows：

```powershell
.\gradlew.bat test plugin --no-daemon
```

Linux：

```bash
bash ./gradlew test plugin --no-daemon
```

产物为 `build/libs/spw-lyrics-<version>.spmod`，版本来自 Gradle。安装包携带 Salt UI 等插件依赖，Kotlin、Compose、Skiko、JNA 及对应原生渲染库由 SPW 提供；调整依赖时保持宿主编译接口一致，避免重复打包及原生库文件锁。

## 代码导航与数据流

主要流程：**Provider 搜索 → 匹配录音 → 读取并解析歌词 → 按偏好选择 → 缓存与输出**。

| 目录 | 职责 |
| --- | --- |
| [domain](../src/main/kotlin/dev/gaboron/spwlyrics/domain) | 曲目、候选、歌词模型、匹配和偏好规则 |
| [provider](../src/main/kotlin/dev/gaboron/spwlyrics/provider) | 来源协议、搜索、详情和网络失败处理 |
| [codec](../src/main/kotlin/dev/gaboron/spwlyrics/codec) | TTML / QRC / KRC / YRC / LRC 解析，编辑和输出格式转换 |
| [application](../src/main/kotlin/dev/gaboron/spwlyrics/application) | 自动与手动搜索、任务协调、选择、预缓存和批量处理 |
| [storage](../src/main/kotlin/dev/gaboron/spwlyrics/storage) | 缓存、单曲设置、音频标签及文件事务 |
| [integration](../src/main/kotlin/dev/gaboron/spwlyrics/integration) | SPW 接入、配置、工作区、Hook、播放与解码适配 |

新增来源实现 `LyricsProvider` 和所需 codec；平台协议放在 Provider 内，不依赖 SPW 回调或界面。

### 匹配、缓存与输出约束

- 自动匹配检查歌名、歌手、专辑、时长与录音版本；不确定结果应拒绝，手动选择可明确覆盖。
- 先搜索元数据，按需取歌词正文；实际类型以解析内容为准。只保留所选来源自带的翻译、音译，不跨来源拼接。
- `LyricsPreferences` 是一次解析的不可变快照。选择、渐进式更新和升级使用同一规则，缓存以 `selectionKey` 区分偏好；单曲手动选择不被自动结果覆盖。
- `LyricsLoadCoordinator` 保留三种替换策略，复用有效缓存并渐进更新；失败结果不缓存。`LyricsResolutionTasks` 取消过期任务，交付前检查任务和歌曲身份。
- `LyricsPrecache` 按曲库顺序准备后续最多 3 首，复用同曲任务；它不是宿主播放队列预测。批量处理同样使用可靠匹配，跳过单曲手动选择，结果不触发当前播放刷新。
- `LocalTtmlLyricsLoader` 独立读取本地 TTML，普通本地歌词交还 SPW，不作为在线来源或在线失败。优先级见[使用说明](使用说明.md#本地歌词处理)。
- `FileLyricsCache` 保存文档、编码、模型版本及偏好标识，TTML 同时保存原始 XML；模型或编码版本不兼容时按需失效。`LyricsOutputRouter` 统一提供普通歌词与原始 TTML。

### 来源维护

各来源能力与要求见[自动加载](使用说明.md#自动加载)。维护协议时同时检查 HTTP 状态、业务错误和响应结构，隔离单个来源失败，并保留超时与取消：

- `AmllIndexStore` 查询全量原始索引，下载和刷新始终在后台进行；已有索引用于当前查询，首次无索引时也不等待网络下载，完成后通知搜索更新。索引有效期 6 小时，失败重试间隔为无文件时 30 秒、有文件时 5 分钟。
- `QqSearchClient` 协调多接口竞速、期限和取消，`QqSearchProtocol` 负责协议解析；TLS 回退仍校验证书和原始主机名。
- `CandidateMetadata` / `MetadataEnrichment` 按需补充候选详情，`OnlineMetadataImport` 只生成待确认的草稿。MusicBrainz 仅提供元数据，LrcShare 需要用户 API Key，Apple Music 歌词依赖第三方服务。

## 宿主、Hook 与工作区

插件声明 `library-read` 和 `class-transform` 权限。曲库通过公开 `WorkshopApi.library` 接口读取，曲库 ID 仅用于本次启用的元数据补齐和歌曲身份校验，不写入持久缓存键。歌词回调使用已有曲库信息，缺失时长由后台任务查询。

`PluginRuntimeSession` 持有一次启用的配置、任务、曲库信息、工作区和 Runtime 连接，旧回调不访问下一次启用的对象。`LyricsWorkspaceSession` 持有各页 Controller，首次进入时初始化，切换标签保留状态；后台结果回到 EDT 前检查代次和关闭状态。

### Hook 目标缓存与回退

`HostUiIntegration` 在后台读取 `HostUiTargetCache`，命中后创建新的反射桥接；缓存未命中时由 `HostBytecodeIndex` 使用 JVM 25 Class-File API 扫描，再通过结构约束发现唯一目标。Hook 注册、注销及界面状态交付在 EDT 执行，重新检查启停和权限。

完整发现并成功注册后，将目标成员描述写入 `cache/宿主Hook.properties`。缓存按格式、宿主来源路径、实现类、文件大小和修改时间校验，可跨播放器重启复用；不保存索引、ClassLoader、宿主实例或 Hook 句柄。开发目录无法通过目录时间可靠判断类文件变化，因此不复用该缓存。

缓存反射准备失败时使缓存失效并扫描；缓存注册失败时先完成回滚，再使缓存失效并扫描。每次启用最多回退重扫一次。停用、撤权不触发重试，回滚失败时停止重新注册。菜单或材质的部分失败沿用原有降级入口，部分结果不缓存。

`HostUiBridge` 负责反射与宿主状态边界，`HostUiHooks` 接入页面、顶部入口与离开确认，`HostPlayerMenu` 追加播放器菜单。打开管理页会先收起宿主展开的播放器，离开时恢复宿主页面；动态发现不能保证任意结构变更后仍兼容。

### 歌词刷新与 TTML 互通

dev23 尚无正式的当前歌词重载接口，`ReflectiveLyricsRefreshBridge` 通过宿主歌词加载器按歌曲身份请求刷新。宿主升级时需重点验证，失败恢复见[常见问题](常见问题.md#文字正确但时间不准)。

`JmxTtmlReceiver` 使用 JDK JMX 对接 [AMLL into SPW 协议 1](https://github.com/GaBoron/AMLL-into-SPW/blob/main/docs/TTML互通.md)，不依赖对方 JAR。`LyricsOutputRouter` 保留原始 XML，将单曲偏移单独传递，同时继续提供普通 SPW 歌词；拒收、不可用或异常时保留普通输出。

提交、撤回和接收器状态变化由同一输出线程协调，检查歌曲、选择及偏移代次，防止迟到结果覆盖新状态；切换选择、停用时撤回外部结果。AMLL into SPW 自行读取的本地 TTML 优先，详见[用户说明](使用说明.md#与-amll-into-spw-一起使用)。

## 文件写入与分析资源

`FileAudioMetadataStore` 按路径协调写入，只修改选中的标签、歌词和图片。事务在系统临时目录暂存、校验，再提交并读回；`AudioTagFileCommit` 处理占用和失败回退。回退失败时保留恢复副本并报告路径；其余事务文件交给系统回收站，不可回收时保留并提示位置。

歌词编辑使用 TTML 保留未修改的扩展信息，写入由 `MetadataLyricsExport` 按所选格式生成；有损格式在确认前列出损失，缺失时间轴时不生成虚构时间。批量写入复用同一文件事务，来源空值不覆盖已有内容。

`SpwTimingPlayback` 适配宿主时钟和播放操作，`SpwTimingAudioDecoder` 向 SPW Media Runtime 租用 FFmpeg。取消或停用只发起终止，不同步等待子进程；`AnalysisProcess` 观察实际退出后释放租约，`TimingMediaRuntime` 在后台关闭连接。进程异常、连接恢复和快速启停都必须保留代次校验及租约保护。

## 验证与诊断

构建后直接检查 `.spmod`：`classes/META-INF/MANIFEST.MF` 中版本和权限应与 Gradle 一致，配置为 `classes/preference_config.json`；携带所需插件依赖，不重复打包宿主 Compose / Skiko 等运行时。`test` 若显示 `NO-SOURCE`，表示没有执行测试用例。

真实 SPW 验收至少覆盖：

- 首次扫描、命中缓存、缓存接入失败回退、撤权和反复启停；检查顶部入口、播放器菜单、导航及草稿确认。
- 快速切歌、慢网络、本地歌词及三种替换策略；检查自动、手动、预缓存和批量结果不串曲。
- 标签、封面、四种歌词写入格式与有损确认；检查占用、外部修改、失败回退和保存后刷新。
- 分词、打轴、频谱拖动、分析中切页或停用，以及 Runtime 重启；核对时间精度、撤销及资源释放。
- TTML 声部、背景、翻译、音译、注音、单曲偏移和接收器恢复；核对目标系统及多插件环境。

在 SPW 日志搜索 `性能统计`，按 `session` 区分启用轮次。启动、停用、入口就绪、后台 Runtime 清理完成及运行期间每 60 秒输出累计汇总，不逐次记录回调，也不包含曲名或路径。

| 指标 | 用途 |
| --- | --- |
| `START` / `STOP` 与初始化阶段 | 定位同步启停成本 |
| `HOST_READY`、`host ready: cache` / `host ready: scan` | 比较入口就绪总耗时及缓存、扫描路径 |
| `HOST_CACHE_READ` / `HOST_PREPARE` / `HOST_CACHE_INSTALL` / `HOST_SCAN` | 区分缓存读取、反射准备、注册与完整扫描成本 |
| `HOST_CACHE_FALLBACK` | 缓存接入失败回退次数 |
| 回调指标、`SEARCH_QUEUE`、`pendingPeak`、`cancelled` | 检查回调耗时、排队等待、未完成歌曲任务峰值和取消 |
| `DECODE` / `MEDIA_CLEANUP` | 解码及后台连接清理耗时，解码指标不含频谱计算 |

耗时以微秒显示，并汇总调用次数、平均 / 最大耗时和 EDT 调用次数。比较相同操作与环境下的冷启动、缓存命中、慢网络和多插件表现，区分插件计时、真实注入与界面响应；离线 benchmark、构建和包检查不能替代宿主验收。
