# 🧰 开发与构建

SPW Lyrics 使用 Kotlin/JVM 21，并包含一个自包含的 WinUI 3 x64 手动搜索伴随程序。

## 环境要求

- JDK 21
- .NET 8 SDK
- Windows x64

## 构建

```powershell
.\gradlew.bat test plugin
```

可导入的插件包生成到：

```text
build/libs/plugin-spw-lyrics-0.4.0.spmod
```

## 代码结构

- `domain`：统一的曲目查询、歌词候选、歌词文档和匹配评分。
- `codec`：解析 TTML、QRC、KRC、YRC、LRC，并编码为 SPW 接受的格式。
- `provider`：AMLL、QQ、酷狗、网易云和本地回退的独立适配器。
- `application`：来源决策、缓存、后台搜索、批量预缓存和切歌竞态控制。
- `storage`：插件缓存布局和歌词缓存。
- `integration`：dev21 曲库与快捷键 API 适配、SPW 扩展点、WinUI 手动搜索/批量处理窗口和自动刷新兼容桥。

AMLL 只下载并持久化索引，建立元数据与平台 ID 查询结构；命中后只下载一个 TTML 文件，不会在运行时遍历整个歌词仓库。新增来源时应实现独立 Provider 和格式适配，不把平台逻辑耦合到播放回调或界面。

## 歌词来源与获取方式

所有在线来源都先搜索歌曲元数据，再对候选进行匹配，只有需要检查或使用的候选才会下载歌词正文。插件不会读取或上传本地音频，也不要求用户登录任何音乐平台。

| 来源 | 搜索与获取流程 | 歌词格式与补充数据 | 主要参考 |
| --- | --- | --- | --- |
| AMLL TTML DB | 每次搜索前检查统一缓存目录中的 `AMLL 索引/index.jsonl`；成功更新后 24 小时内复用，失败后每小时最多重试一次，并重建曲名、歌手和平台 ID 内存索引。命中后从仓库的 `am-lyrics` 目录下载单个文件。 | TTML，通常包含逐字时间、对唱和背景歌词。 | [AMLL TTML DB](https://github.com/amll-dev/amll-ttml-db) |
| QQ 音乐 | 调用桌面端搜索接口取得歌曲 `musicId`，再请求歌词下载接口；解码原文 QRC，并分别读取翻译和音译轨道。 | QRC 或 LRC；合并逐字时间、翻译和音译。 | [Lyricify Lyrics Helper](https://github.com/WXRIW/Lyricify-Lyrics-Helper)、[Lyrico](https://github.com/Replica0110/Lyrico) |
| 酷狗音乐 | 搜索歌曲取得文件 Hash，再按歌曲信息和时长搜索歌词候选；使用候选的 `id` 与 `accesskey` 下载 Base64 KRC 并解密。 | KRC，包含逐字时间，存在时保留内嵌翻译。 | [Lyricify Lyrics Helper](https://github.com/WXRIW/Lyricify-Lyrics-Helper)、[Lyrico](https://github.com/Replica0110/Lyrico) |
| 网易云音乐 | 优先使用 PC 云搜索接口，失败时回退旧搜索接口；歌词优先请求 EAPI `song/lyric/v1`，失败时回退公开歌词接口。 | 优先解析逐字 YRC，没有时使用 LRC；合并新版或旧版翻译、音译轨道。 | [Lyricify Lyrics Helper](https://github.com/WXRIW/Lyricify-Lyrics-Helper) |
| SPW 本地歌词 | 不是网络 Provider。插件没有合适结果，或用户明确切回本地歌词时，交还 SPW 处理内嵌歌词和同名 `.lrc`。 | 由 SPW 决定。 | [SPW 创意工坊 API](https://github.com/Moriafly/spw-workshop-api) |

QQ 音乐、酷狗音乐和网易云音乐使用的是客户端或网页使用的公开网络端点，并非平台承诺长期稳定的开发者 API。接口地址、参数或返回结构改变时，对应 Provider 可能需要更新；单个来源失败不会阻止解析器继续尝试其他来源。

## 统一处理流程

1. Provider 将平台响应转换为统一的歌曲候选，只保留匹配需要的曲名、歌手、专辑、时长和平台 ID。
2. 匹配器排除明显的 Live、Remix、伴奏等版本冲突，并综合元数据相似度和时长选择候选。
3. 下载并解析歌词正文后，以实际内容判断逐字、逐行或普通歌词，不直接相信搜索接口的类型提示。
4. 自动选择先检查所有来源的逐字歌词，再回退逐行和普通歌词；类型相同时按 AMLL、QQ、酷狗、网易云的顺序选择。
5. 只保留所选来源自带的翻译和音译，不进行跨来源补充。
6. 最终文档编码为 SPW 接受的格式并写入缓存，不插入歌词来源说明行；手动预览会复用搜索阶段已下载的歌词。

开发分支基于 Workshop API `0.1.0-dev21` 和 SPW 1.19，使用 `WorkshopApi.library.getAllTracks()` 取得曲库快照及 `MediaItem.duration`。曲库 ID 只用于当前插件会话内补齐歌词回调元数据，不写入持久缓存。批处理复用同一个 `LyricsResolver` 和 `FileLyricsCache`，不调用播放刷新桥，也不写回 SPW 曲库。批处理层限制为三首歌曲并行，同一批次按曲名、歌手、专辑和近似时长复用重复录音的解析结果；`LyricsResolutionProgress` 从解析层向上报告来源搜索和选择阶段。页面只负责勾选范围、轮询快照并增量更新可虚拟化列表。

插件使用 `com.xuncorp.spw.workshop` Gradle 插件打包，申请 `library-read` 与 `key-bindings` 权限。手动搜索通过 `WorkshopApi.playback.getCurrentMediaItem()` 读取当前歌曲；快捷键通过 `keyBindingManager` 注册，由 SPW 处理自定义键位、冲突和全局绑定。自动刷新所需的反射桥仍保留，因为 dev21 尚无重新加载当前歌词的正式接口。该分支不兼容 dev20 或 SPW 1.19 之前的版本。

## 项目与实现参考

- [SPW 创意工坊 API](https://github.com/Moriafly/spw-workshop-api)：插件生命周期、设置和歌词加载接口。
- [AMLL TTML DB](https://github.com/amll-dev/amll-ttml-db)：AMLL 逐字 TTML 数据及元数据索引。
- [Lyricify Lyrics Helper](https://github.com/WXRIW/Lyricify-Lyrics-Helper)：QQ、酷狗、网易云接口，QRC/KRC/YRC/TTML 解析和网易云 EAPI 实现参考。
- [Lyrico](https://github.com/Replica0110/Lyrico)：多来源歌词、逐字格式和歌词元数据处理参考。
- [OpenCC4J](https://github.com/houbb/opencc4j)：跨字形匹配。
