# 使用说明

本文只介绍插件的实际使用方式。构建、Provider 和 Workshop API 相关内容见 [开发与构建](开发说明.md)。

## 自动加载

启用 SPW Lyrics 后正常播放歌曲即可。没有可用缓存时，插件会在后台搜索歌词；搜索期间 SPW 可以继续显示内嵌歌词或同名 `.lrc`。

本地歌词内容是 TTML 时，插件会在播放加载阶段直接转换：支持音频内嵌歌词、同名 `.ttml` 文件，以及内容实际为 TTML 的同名 `.lrc` 文件。已有普通 `.lrc` 或普通内嵌歌词仍交给 SPW 加载；同名 `.lrc` 优先于 `.ttml`。TTML 解析失败时，插件不替换原有本地歌词。此转换不需要手动选择歌词源，也不会等待在线搜索。

自动结果先比较歌词质量，再比较来源优先级：

1. 逐字歌词
2. 逐行歌词
3. 普通歌词

歌词质量相同时，来源顺序为：

1. AMLL TTML DB
2. QQ 音乐
3. 酷狗音乐
4. 网易云音乐

匹配时会综合歌名、歌手、专辑和歌曲时长，并尽量排除明显的 Live、Remix、伴奏、翻唱等版本冲突。

首次搜索不会无限等待所有来源。插件会在约 10 秒内先应用当时最合适的结果，剩余来源继续在后台完成；如果之后找到更高质量或同质量但优先级更高的歌词，缓存和当前歌词可能再次更新。

如果所有来源都没有可靠结果，插件会保留 SPW 本地歌词，并提示尝试手动搜索。失败结果不会写入歌词缓存，下次播放仍会重新尝试。

## 自动替换策略

进入“设置 → 创意工坊 → 模组设置 → SPW Lyrics → 自动替换歌词”可以选择：

- `始终优先使用插件歌词`：每首歌都自动搜索并优先使用插件结果。
- `仅在本地无歌词时补充`：优先保留 SPW 的内嵌歌词或同名 `.lrc`，本地没有歌词时再搜索。
- `仅手动选择时替换`：关闭自动搜索，只使用手动选择过的歌词。

单曲的手动选择优先于全局策略。某首歌手动选择“切回本地歌词”后，也会保持本地歌词，直到你在手动搜索标签页恢复自动匹配。

## 手动搜索

点击播放器底部“更多 → 手动搜索歌词”可直接搜索当前歌曲。SPW 顶部的“歌词管理”图标默认打开批量处理，页面包含手动搜索、元数据编辑和批量处理三个标签页；这些入口需要类变换权限。切换标签不会丢失候选、预览或未保存的草稿。

返回或离开页面前会检查元数据草稿。主窗口接入失败时会显示原因，请检查权限并重新启用插件；仍无法使用时请反馈 SPW 版本及异常。

页面打开后会使用当前歌曲信息进行搜索。你可以：

- 修改搜索关键词；
- 搜索全部来源或指定一个来源；
- 查看候选的歌曲名、专辑、时长、歌词类型和匹配分；
- 预览候选歌词后再应用；
- 恢复自动匹配；
- 切回 SPW 本地歌词。

候选中的“逐字”“逐行”“普通”来自歌词实际解析结果，不依赖搜索接口的预估类型。手动选择会按歌曲保存，不会被之后的自动搜索覆盖。

搜索操作区旁显示各词源状态：灰色“未检查”、蓝色“处理中”、绿色“可用”、红色“失败”、黄色“超时”，悬停可查看简短原因。请求正常但没有候选时仍显示“可用”；更改关键词或来源后，状态会重置，点击搜索后重新检查。状态只来自实际请求，不会额外定时探测网络。

AMLL 会区分“本地索引可用”和在线索引操作。本地索引可搜索不代表当前网络正常；更新失败时仍可搜索旧索引，并显示“更新失败（使用本地索引）”。首次获取失败时会提示“索引获取失败”，请检查网络后重试。

宽页面左侧显示搜索结果，右侧显示歌词预览。“排序”菜单可按匹配度、来源、歌名等排序，点击候选即可预览；“应用歌词”“导入元数据”和歌词切换操作位于页面底部。时长与来源、类型、匹配分一起显示，选中标记不会挤动文字。两处歌词预览均显示主唱、对唱和背景人声，并按左右声部对齐。输入关键词后按 `Enter` 搜索，列表中用方向键切换候选，确认后可按 `Ctrl+Enter` 应用。`Ctrl+F` 聚焦搜索框，`F5` 刷新当前歌曲。

歌词管理使用透明页面底层和 Salt UI 分组控件，底部为播放条留白。较窄的页面通过“搜索结果 / 歌词预览”切换查看，元数据页通过“歌曲信息 / 内嵌歌词”切换；窗口较矮或放大显示时可滚动页面。

切歌后，请点击“刷新歌曲”更新搜索对象。页面中的歌曲与当前播放不一致时，应用歌词、切换策略或保存延迟会被拒绝，避免误改另一首歌。

### 调整歌词延迟

展开歌词预览下方的“时间调整”，输入毫秒数，或用 `−100`、`+100` 调整，再点击“保存”。正数表示歌词延后，负数表示歌词提前，例如歌词比声音早 500 毫秒时，填入 `500`。范围是 -60000 到 60000 毫秒，可点击“重置”取消调整。

延迟按每首歌保存，重启后保留。预览时间会随输入同步变化，保存后插件会请求刷新当前歌词；没有立即变化时，可切到其他歌曲再切回来。调整同时影响逐行和逐字时间，不修改缓存里的原始时间轴或本地歌词文件。

这项调整适用于插件提供的在线歌词和转换后的本地 TTML。普通内嵌歌词、普通 `.lrc` 和没有时间轴的纯文本歌词不受影响。

## 编辑歌曲元数据和内嵌歌词

点击播放器底部“更多 → 编辑元数据”，或切换到歌词管理的“元数据编辑”标签页。首次进入会读取当前播放歌曲，也可点击“打开歌曲”选择本地音频。支持 MP3、FLAC、M4A、MP4、OGG、WAV 和 AIFF；暂不支持 Opus 等其他格式。

歌曲信息区可以修改歌曲名、歌手、专辑、专辑歌手、发行日期、流派、音轨号、碟片号、作曲和备注。输入框采用统一最小高度，多值标签和备注随内容增高；多值标签每行填写一个值。内嵌歌词区提供“逐句编辑”“编辑原文”和“歌词预览”，也可点击“导入歌词”。只支持 TTML、LRC、增强 LRC 和 SPL；文件扩展名为 `.ttml`、`.lrc`（包括增强 LRC）和 `.spl`，编码支持 UTF-8 或带 BOM 的 UTF-16。

“逐句编辑”中点击“添加歌词”可在当前句后插入新句，没有歌词时也可新建。在列表中选择句子；较窄的编辑区通过句子菜单切换。选中后可直接修改：

- 本句的开始、结束时间，以及每个字或词的开始、结束时间。填写 `mm:ss.mmm`、`hh:mm:ss.mmm` 或毫秒数；`−100 ms`、`+100 ms` 同时平移本句和逐字时间。
- 点击“主唱（左）”“对唱（右）”设置显示侧。保存为 TTML 时会同步整理演唱者定义和歌词行标记，使主唱靠左、对唱靠右，包括第一句就是对唱的情况；未选中句子的左右侧保留，预览也按左右显示。勾选“背景人声”设置背景歌词，取消勾选可改回独立主歌词。
- 直接修改正文、翻译和音译。替换整句正文会清除本句逐字时间；逐字列表可单独修改各字、词并保留时间。含注音等嵌套标记的单词在此仅改时间，其文本可在“编辑原文”中修改。

按住 `Ctrl` 点击可多选或取消选择，按住 `Shift` 点击可连续选择，`Ctrl+Shift` 可追加连续选择。在歌词列表中按 `Ctrl+A` 全选、`Delete` 删除所选，也可点击对应按钮。多选后可统一设置延迟（整数毫秒，负数表示提前）、主唱（左）、对唱（右）、背景或取消背景；延迟同时移动各句及其逐字时间。右侧的演唱声部和背景人声控件应用于全部所选句子，背景状态混合时再次勾选会统一设为背景。正文、时间、翻译和音译仍只修改当前句。

导入同一时间戳的原文和译文时，会依据语言特征将译文归入“翻译”；可识别的拼音、罗马音归入“音译”。各自有逐字时间的同时间歌词会保留为独立句；无法确定的内容可在编辑区核对、修改。

修改会自动进入草稿，切换句子时保留。无效时间会提示并阻止写入。逐句编辑使用 TTML 保留声部、背景和逐字信息，且只修改对应 XML 节点，保留未编辑的注音、自定义标签和元数据；需要其他格式时再转换。自动生成、转换的 TTML 会为外层结构和每句歌词换行缩进，逐字标签仍在同一句内，避免把缩进变成歌词空白。“编辑原文”可直接修改完整文本。

要使用在线搜索的歌词，在手动搜索标签页选中并预览候选，点击“导入元数据”。候选会作为草稿导入搜索时对应的歌曲文件，顶部会显示目标路径；不需要先应用为插件歌词。元数据编辑标签页里的“搜索歌词”可打开手动搜索。

页面底部集中放置歌词搜索、导入、格式转换和写入操作。在格式菜单中选择格式，再点击“转换格式”。搜索来源内部的 QRC、KRC、YRC 等会先解析成统一歌词，再按所选格式导入；本地文件导入仍只支持上述四种格式。

- TTML 保留原始 TTML 的完整 XML，包括声部、背景人声、翻译、音译、注音及歌词元数据；其他来源会生成 TTML。
- LRC 保留逐行时间、翻译和音译，不保留逐字时间、声部和注音。
- 增强 LRC 使用尖括号记录逐字时间；来源没有逐字时间时只保留逐行时间。
- SPL 使用椒盐歌词的逐字标记和显式行结束时间。增强 LRC 和 SPL 也无法表达 TTML 的声部、注音等扩展内容。

切换格式反复转换时，会尽量使用此次导入或转换前的歌词文档，避免先转 LRC 再转回 TTML 时丢失原来的逐字信息；手动修改原文后以修改后的内容为准。缺少时间轴的搜索结果只能生成 TTML，不会凭空生成时间戳。

点击“歌词预览”检查内容，再点击“写入歌曲文件”或按 `Ctrl+S` 保存。清空歌词原文后保存可清除内嵌歌词。导入和编辑只修改页面中的草稿，保存时才会修改音频文件；关闭或读取其他歌曲前会提示未保存的修改。切歌不会改变页面里正在编辑的文件，顶部路径始终是保存目标。`F5` 或“重新读取”可以重新载入该文件。

保存只修改编辑过的标签，保留封面及其他标签。插件先在系统临时目录写入并校验，再提交到原文件并读回检查；写入或校验失败时回退原文件。事务结束后清理临时文件，不在歌曲目录生成备份或编辑副本。文件已被其他程序修改时，需重新读取后再保存；如果播放器或同步程序禁止写入，草稿会保留，请先切换到其他歌曲、等待同步完成后重试。

页面底部的“AMLL 编辑器”可打开 [AMLL TTML TOOL](https://amll-ttml-tool.stevexmh.net/)，用于更复杂的歌词制作。

写入后会尝试刷新当前歌曲的歌词。歌曲名等信息需重新扫描 SPW 曲库后更新。如果仍显示在线歌词，请在手动搜索标签页选择“切回本地歌词”；同名 `.lrc`、`.ttml` 可能有更高优先级，请同时检查旁边的歌词文件。此编辑页面会修改音频文件，自动搜索和批量缓存仍不修改音频。

## 批量处理音乐库

第一次使用插件，或一次加入了很多歌曲后，可以打开“批量处理音乐库”提前建立缓存。

切换到歌词管理的“批量处理”标签页。页面显示曲库、单曲进度、任务概览和任务操作。切换标签或关闭页面后任务继续运行，重新打开可查看当前进度；要结束任务，请点击“停止”。

批量处理会读取 SPW 已扫描的音乐库，使用与自动播放相同的匹配和歌词选择规则，但不会修改音频文件或 SPW 音乐库本身。

使用时可以：

- 只勾选需要处理的歌曲；
- 默认跳过已有缓存，或选择重新处理；
- 暂停、继续和停止任务；
- 处理完成后单独重试失败项。

音乐库扫描完成后，可点击“刷新音乐库”更新列表。任务操作位于页面上方；处理期间不能更改歌曲范围。

“重新处理已有缓存”与全选等列表设置放在同一操作区。处理时列表会平滑跟随正在搜索的歌曲；滚轮、拖动滚动条或键盘浏览会暂停跟随，最后一次操作后空闲 3 秒会自动恢复。

批量处理最多同时处理 3 首歌曲。相同录音会尽量复用同一份搜索结果，避免重复请求。界面会显示总体进度和单曲状态，包括搜索歌词、选择结果和写入缓存等阶段。

停止任务不会删除已经成功写入的缓存。没有可靠匹配的歌曲也不会写入错误结果，之后正常播放时仍会重新搜索。

## 支持的歌词内容

插件可以处理 TTML、QRC、KRC、YRC 和 LRC，并尽量保留来源中已有的：

- 逐字或逐行时间轴；
- 翻译；
- 音译；
- 对唱；
- 背景歌词；
- 同一时间播放的多行歌词。

歌词使用所选来源自带的翻译和音译。普通歌词输出会过滤在线歌词中的歌名署名页、词曲与制作人员信息，播放时从第一句歌词开始显示；传给 AMLL into SPW 的原始 TTML 保持来源的完整 XML。

## 与 AMLL into SPW 一起使用

同时启用支持 TTML 互通的 [AMLL into SPW](https://github.com/GaBoron/AMLL-into-SPW)，并授予它所需的权限后，SPW Lyrics 会直接提供原始 TTML，让原生歌词渲染保留完整的逐字时间、演唱者、背景人声、翻译、音译和注音。只有来源本身提供的内容才能保留；同时继续向 SPW 提供带时间轴的普通歌词，供灵动词岛等插件读取。

本地同名/内嵌 TTML、已有原始缓存、自动搜索、手动应用和后台质量升级均支持此方式。两个插件的启用顺序不限，后启用时会重新提供当前歌曲；AMLL into SPW 的接收状态不影响 SPW 的普通歌词输出。

保存单曲延迟时，原始 XML 保持不变，延迟单独传递。AMLL into SPW 优先读取它找到的本地 TTML，其顺序为同名 `.ttml`、内嵌 TTML、同名 `.lrc` 中的 TTML，再使用 SPW Lyrics 提供的结果；接口延迟只作用于最后一种。若想让在线选择和它的单曲延迟生效，请先移走优先的本地 TTML；继续使用本地 TTML 时，需调整该文件的时间轴。

“切回本地歌词”会撤回当前歌曲的外部结果；“恢复自动匹配”会先撤回旧选择，再重新搜索。若仍显示不想要的歌词，先检查是否存在优先的本地 TTML，再按 [常见问题](常见问题.md) 排查。

## 本地缓存

插件缓存默认位于：

```text
%LOCALAPPDATA%\SPW Lyrics\cache
```

也可以在插件设置中点击“查看本地缓存文件夹”直接打开。

缓存目录中主要包含：

- `歌词`：自动或手动取得的歌词，TTML 会保留原始 XML；删除后，下次播放会重新获取。缺少原始 XML 的旧 TTML 缓存会按需重新获取，手动选择仍保留。
- `手动匹配`：每首歌的手动选择；删除后，该歌曲恢复自动匹配。
- `AMLL 索引`：AMLL TTML DB 的本地索引缓存；删除后会在需要时重新下载。

修改或删除缓存文件前建议先关闭 SPW，避免和正在进行的搜索或写入同时发生。

## 网络与隐私

在线搜索时，插件会把当前歌曲的歌名、歌手、专辑和时长发送给相应歌词服务。批量处理时，会对所选歌曲逐首发送这些信息。

插件通过 SPW 的曲库接口读取歌曲元数据，不需要登录音乐平台账号。本地 TTML 转换会读取外置歌词或音频中的歌词标签，不会修改或上传音频文件内容。元数据编辑页面只在点击“写入歌曲文件”时修改所选本地文件，不会上传音频或导入的歌词。
